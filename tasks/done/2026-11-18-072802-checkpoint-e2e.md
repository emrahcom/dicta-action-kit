# Checkpoint end-to-end test

The server runs with `PLANS_PER_CHECKPOINT=1`, and one test covers a checkpoint
with the server and the client together (`e2e.md`, Setup and Tests).

- `playwright.config.ts`: the server's `env` gets `PLANS_PER_CHECKPOINT: "1"`.
- `e2e/confirmations.spec.ts`: a request with two plans that each change a task
  on Teamboard; the second has a `progress`.
  - Continue: the confirmation view shows the `progress` before the second plan
    runs; after Continue both changes are in the site's data, and the history
    holds the request as done with both plans.
  - Cancel: only the first change is in the site's data, and the history holds
    the request as cancelled, with halt `cancelled` at step 1 of the second
    plan.

Check: `npm run check`, `npm run lint` and `npm run test:e2e` pass.
