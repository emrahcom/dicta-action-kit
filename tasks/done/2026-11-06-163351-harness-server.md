# Harness server

Give `dicta-action-harness` its `npm run server`, as `specs/harness.md` (The
check) describes.

- `package.json`: the script `server`, which runs
  `node_modules/dicta-action-server/src/index.ts` with `tsx` and its settings
  from `.env`, when the file exists.
- `.env.example`: every setting of `architecture.md` (Configuration) in
  `dicta-action-server`, with a short comment each; `PLANNER=claude`,
  `PORT=8080`, empty values for the key and the secret.
- `docs/checking-the-module.md` (Trying it on the running site) and
  `docs/adding-dicta.md` (The server): copy `.env.example` to `.env`, fill it
  in, run `npm run server`; the site's `server` attribute and its token endpoint
  point to it. For production, the server runs on its own, as its README says.
- `AGENTS.md`, step 6: start the server with `npm run server`; ask the developer
  for the key and the secret, and never write them anywhere but `.env`.
- In the kit, `test:harness`: `npm run server` starts with `PLANNER=stub` and
  `ALLOW_UNAUTHENTICATED=true` on a free port and answers a round.
