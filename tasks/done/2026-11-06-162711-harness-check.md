# Harness check

Give `dicta-action-harness` its check, as `specs/harness.md` (The check,
Contents) describes. `npm run server` comes in a later task.

- `package.json`: `dicta-action-js` `0.1.1`; `dicta-action-server` as a git
  dependency pinned by commit; `tsx`, `happy-dom` and `typescript`; the script
  `check`. `package-lock.json` is committed.
- `tsconfig.json` at the root, for the sites' modules to extend.
- `.gitignore`: `node_modules/`, `.env` and every `tsconfig.local.json`.
- The check command, in a folder of its own such as `check/`: for one site or
  every site, with the type check, `buildContext` and `checkContext`, the
  module rules, the two warnings, and the case of a module that cannot be
  loaded. Its messages name the site, the capability and what to fix, in
  simple English.
- `docs/checking-the-module.md`: running the check, reading its messages, the
  site's `tsconfig.json` and `tsconfig.local.json`, and trying requests on the
  running site.
- `AGENTS.md`: step 4 runs the check; a new site's folder gets its
  `module/tsconfig.json`; updating the harness adds `npm install` and the check
  on every site. `README.md`: `npm install` after making the copy.
  `docs/upgrading.md`: "the checks" back in the list of parts.
- In the kit, `npm run test:harness`: runs the harness check with
  `node --test` on small modules in `e2e/harness/`, one good and one for each
  error and warning, and on the reference module. Not part of `test:e2e`.
