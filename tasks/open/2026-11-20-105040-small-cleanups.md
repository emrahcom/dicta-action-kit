# Small cleanups

Code quality fixes from the review of 2026-11-20 of the kit's code and the
harness's check script, with no change in behaviour. The larger moves come in a
later task.

Kit (`e2e/`):

- `e2e/setup.ts`:
  - exports `say(page, text)`; `submit` sends its replies through it, and the
    LLM check uses it in place of its own copy;
  - exports the round path, `SITE` and a helper that collects the round
    responses as they arrive, used by the specs and the LLM check in place of
    their own copies;
  - `open(page)` loses the `path` parameter no caller passes;
  - `fileFor` moves up next to the other helpers.
- `e2e/llm/llm.spec.ts`: one helper for reading the page while a page may be
  loading, in place of three copies of the same `try`; its `ended` is named
  `newest`, since `setup.ts` has an `ended` that does something else.
- `e2e/llm/harness-site.ts`: `config` is named `readConfig`.
- `e2e/harness/`: one small shared file with the harness path and the "run npm
  install in the harness first" check, used by both test files. The twelve check
  tests that differ only in their site, exit status and pattern become one
  table, with the same names.
- `e2e/confirmations.spec.ts`: the page type is `Page`, imported from
  Playwright.
- `e2e/module/teamboard.ts`, the reference module: the helper `title` is named
  `taskTitle`, so `tasks.add` reads its arguments like the other capabilities,
  and the local `teammate` is named `person`, as elsewhere in the file.
- `e2e/harness/sites/no-tsconfig/module/index.ts`: its comment says what the
  fixture is: the good module, without its `tsconfig.json`.

Harness (`scripts/check/`):

- `index.ts`: a missing site folder is the first error of `checkSite`, printed
  like any other error, with the same text; the two "is missing" checks become
  one.
- `load.ts`: the context size message uses its constant; the capability type is
  named next to the other types; the comment on naming a capability by its place
  moves to the line it explains. `MARK` notes that it must match the one in
  `index.ts`.

Type check: the kit's `npm run check` also checks
`../dicta-action-harness/scripts/check/`, which no type check covered.

Check: Prettier `--check` on the harness from the kit, `npm run check` in the
harness, and `npm run check`, `npm run lint`, `npm run test:e2e` and
`npm run test:harness` in the kit pass.
