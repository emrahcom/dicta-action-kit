# Example site API

Add the tasks API and its in-memory store to `dicta-example-site`, per
`example-site.md` (App, Structure).

- Store: tasks and teammates in memory. A few sample tasks and three teammates
  at start. Task ids like `t1`, teammate ids like `anna`.
- JSON API:
  - `GET /api/tasks`: all tasks; `?q=` keeps those whose title contains it,
    ignoring case.
  - `POST /api/tasks`: adds a task from `title`, `due` and `assignee`; `201`
    with the task.
  - `GET /api/tasks/<id>`: one task.
  - `PATCH /api/tasks/<id>`: changes any of `title`, `due`, `done` and
    `assignee`; returns the task.
  - `DELETE /api/tasks/<id>`: deletes it; `204`.
  - `POST /api/tasks/<id>/share`: shares it with `teammate`. The server logs the
    email it would send; `204`.
  - `GET /api/teammates`: all teammates.
  - `POST /api/reset`: restores the sample data; `204`.
- Checks, as a real backend would: `title` is a non-empty string of at most 200
  characters; `due` is a real date as `YYYY-MM-DD` or `null`; `done` is a
  boolean; `assignee` and `teammate` are teammate ids, `assignee` may be `null`;
  unknown fields are refused. A failed check is `400`, an unknown task `404`,
  both with `{ "error": "..." }`.
- Tests for each endpoint and each check.
