# Structure

Structure fixes from the code quality review of 2026-11-20 of the kit's code and
the harness's check script, with no change in behaviour: long code gets named
parts, and shared code lives in one place.

- `playwright.config.ts` and `playwright.llm.config.ts`: the web servers (the
  example site, and `dicta-action-server` with its planner and its command), the
  base URL, one worker and the Chromium permission come from one helper in
  `e2e/setup.ts`, with the type of the `harnessSite` option, so the two configs
  hold only what differs (`e2e.md`, Setup; `llm-check.md`, Running).
- `e2e/llm/llm.spec.ts`, `run()`: its parts become named functions: adding the
  case's tasks, watching the rounds for checkpoints, answering one prompt of the
  element, and listing the problems of a case. `run()` then reads as the steps
  of a case (`llm-check.md`, Cases).
- `e2e/llm/harness-site.ts`: the `*` branch of `harnessImports` becomes its own
  function. The file moves to `e2e/`, since `e2e/setup.ts` uses it for every
  check, not only the LLM check.
- `../dicta-action-harness/scripts/check/load.ts`: the check of the site context
  and the check of the capabilities become named functions, as the steps of
  `index.ts` are (`harness.md`, The check).

Check: Prettier `--check` on the harness's `scripts/` from the kit,
`npm run check` in the harness, and `npm run check`, `npm run lint`,
`npm run test:e2e` and `npm run test:harness` in the kit pass, and the LLM check
still lists its cases.
