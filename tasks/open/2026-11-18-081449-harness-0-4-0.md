# Harness on dicta-action 0.4.0

`dicta-action-server` 0.4.0 and `dicta-action-js` 0.4.0 are released, with
checkpoints, step texts and small exchanges. Move the harness's pins and follow
the changes (`harness.md`, The check, Contents and What it teaches).

Pins (`harness.md`, The check):

- `dicta-action-server` from `v0.3.0` to `v0.4.0`, with its `package-lock.json`
  lines (`version` 0.4.0, `resolved` at commit
  d141d6b56bc9569177760dd7bc85b57d3f42208d), installed with `npm ci`.
- `dicta-action-js` from 0.3.0 to 0.4.0.

`.env.example`:

- `MAX_PLANS`: the most plans for one request, 1 to 100, default 50.
- `PLANS_PER_CHECKPOINT`, commented out, before it: after this many plans the
  user is asked whether to go on, 1 to 20, default 10.

Guides:

- `docs/writing-capabilities.md`, "Keep state and outputs small": a capability
  that creates something returns its id in a small output. A large output is
  dropped from the request after two more plans, and from the history, so an id
  inside it is lost for a later step or an undo.
- `docs/checking-the-module.md`, "Trying it on the running site": a long request
  asks from time to time whether to go on, with a short text on what is done and
  what comes next. Read it and press Continue.

Check: Prettier `--check` on the harness Markdown from the kit, `npm run check`
in the harness, and `npm run check`, `npm run lint`, `npm run test:e2e` and
`npm run test:harness` in the kit pass.
